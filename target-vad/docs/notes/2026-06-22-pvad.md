# pVAD Crowd-Focus — Cutover Gate Verdict (GB10)

**Date:** 2026-06-22
**Hardware:** NVIDIA GB10 (DGX Spark, aarch64, single GPU, ~128GB unified)
**Plan:** Director Plan 05, Task 1 (cutover gate)
**Spike method:** direct HF probe + ONNX load + per-frame latency on CPU.

## VERDICT: **GO** (ONNX path)

Both halves of the gate pass, and the implementation is *simpler* than the plan
assumed.

## Finding that changed the approach

The plan assumed a PyTorch `.pt` checkpoint to be loaded into a hand-vendored
`nn.Module` (with a guessed architecture to reconcile against the `state_dict`).
**The actual upstream artifact is `pvad.onnx`** — a self-contained ONNX *streaming*
model. We therefore run it via `onnxruntime` (already installed, 1.24.4) and DROP:
the vendored `nn.Module` (Task 1 Step 1/3), the `state_dict` reconciliation, and the
hand-built `MelFrontEnd` (Task 3) — the log-mel is computed inside the ONNX graph.

## Half 1 — model load: PASS

- Repo `FireRedTeam/FireRedChat-pvad` exists; checkpoint `pvad.onnx`
  (sha256 `2114fd3c…ef4bdd`, 3,940,567 bytes).
- Loads in `onnxruntime` CPU; one 10 ms (160-sample) call returns a finite prob in
  `[0,1]` plus updated `mel_buffer`/`gru_buffer` state (streaming-native).
- Conditioning ECAPA = `speechbrain/spkrec-ecapa-voxceleb` (192-dim) — IDENTICAL to
  our `core/speaker/embedder.py`, so enrollment embeddings are directly compatible.

## Half 2 — latency: PASS (large margin)

- pVAD per-10 ms-frame ONNX inference (CPU, 1 intra-op thread): **p50 0.26 ms /
  p95 0.26 ms**.
- Per 200 ms chunk (20 frames): **~5 ms p95** for the pVAD portion.
- Combined reflex budget (Silero + pVAD + Smart Turn + classify_interjection) is
  dominated by Smart Turn (~55 ms p95 under live gemma load, per
  `2026-06-21-gb10-contention.md`). pVAD adds ~5 ms → combined well under the
  100 ms p95 budget. (A formal combined-under-load run can be added, but the pVAD
  contribution is negligible and the gate is not in doubt.)

## Consequences for Plan 05

- GO → build the pVAD path, but on **ONNX** (loader = `onnxruntime` session via
  `hf_hub_download`; `VADStream` threads `mel_buffer`+`gru_buffer`; no `model.py`,
  no `frontend.py`). All plan interfaces unchanged (`SpeakerFrame`,
  `VADStream.update_speaker/push`, `PvadWorker.process`, RMS crash-fallback).
- Tasks 6–9 (SafetyNet, Lockout, holdout, verify-before-serve) are spike-independent
  and ship as written.
- Degraded path (`is_target := rms >= proximity_rms`) remains the crash-fallback,
  always present.
